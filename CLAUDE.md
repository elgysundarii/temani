# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project state

`temani` is a Flutter app (thesis prototype: virtual cat pet + chatbot + emotion detection). Stage 1 is a UI mockup: no n8n/LLM/emotion service yet. `MockTemaniApi` (keyword stub) stands in behind the `TemaniApi` interface (`lib/data/temani_api.dart`); local data is in-memory (`lib/app_state.dart`).

Layout: `lib/core` (theme tokens, contrast util, game config), `lib/features/{pet,streak,jar,chat,home,onboarding,history,settings}`, `lib/widgets`, `lib/data`, `assets/config/*.json` (emotion map, fallback replies). Pet transitions live only in `pet_state_machine.dart`. State: Riverpod; routing: go_router.

Design rules (do not break): pet adapts to the user, no care mechanics, no guilt; no clinical claims; stars are earned by telling a story, never by emotion; white text never on yellow; do not invent versions, accuracy numbers, or hotline numbers (use `TODO-VERIFY`/`TODO-USER`). See `docs/`.

## Commands

```bash
flutter pub get                          # install dependencies
flutter run                              # run on the connected device/emulator
flutter analyze                          # lint (flutter_lints via analysis_options.yaml)
flutter test                             # all tests
flutter test test/widget_test.dart       # single file
flutter test --plain-name "<test name>"  # single test by name
```

## Notes

- `analysis_options.yaml` excludes `build/`, `android/`, `ios/`, `web/`, `windows/` from analysis.
- Android debug builds need a few GB of free disk space; a full disk makes Gradle/Kotlin fail with `No space left on device` and cascading errors (missing `.kotlin/errors` logs, "Could not receive a message from the daemon"). Free space first (`flutter clean`, Xcode DerivedData, unused AVDs in `~/.android/avd`) before debugging those errors.

# RTK (Rust Token Killer) - Token-Optimized Commands

## Golden Rule

**Always prefix commands with `rtk`**. If RTK has a dedicated filter, it uses it. If not, it passes through unchanged. This means RTK is always safe to use.

**Important**: Even in command chains with `&&`, use `rtk`:
```bash
# ❌ Wrong
git add . && git commit -m "msg" && git push

# ✅ Correct
rtk git add . && rtk git commit -m "msg" && rtk git push
```
